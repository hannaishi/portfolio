## 送信方式

PHP 8.3以上の標準`mail()`を使用し、Xserverのローカルメール配送機能へ渡す。
SMTP認証のパスワードや追加ライブラリを必要とせず、小規模なフォームを保守しやすくするための選択。
UTF-8の件名と本文をBase64でエンコードしたプレーンテキストメールを1通、固定の送信先へ送る。
差出人とエンベロープFromは設定ファイルの固定メールアドレス。入力されたメールアドレスは検証後のReply-Toと本文だけに使う。
自動返信メールは実装していない。

`mail()`のtrueはサーバーが配送を受け付けたことを示し、受信箱への到着を保証しない。
PHPがtrueを返した場合だけ、画面へ成功を返す。配送結果、迷惑メール判定、受信確認は本番で別途確認する。

## 未設定・GitHub Pages・JavaScript無効時

- 設定ファイルがない、メールアドレスが空、設定値や保存先が不正なら送信無効。
- HTMLには準備中の案内を初期表示。PHPの設定確認に成功したときだけ入力案内に切り替える。
- GitHub Pages（`*.github.io`）ではAPIを呼ばず、準備中のまま。独自ドメインの静的ホストでもPHP実行・JSON応答がなければ有効化しない。
- HTMLの404、PHPのソース、通信エラーを成功扱いにしない。
- JavaScript無効時も準備中表示を維持。直接POSTしてもJSON形式・セッション・CSRF検証が通らず送信できない。
- 設定済み環境の送信中はボタンを無効化し、`aria-busy`とライブリージョンで状況を伝える。
- 失敗時は入力を保持し、サーバー側入力エラーを既存の項目別表示へ反映する。
- タイムアウト後は失敗表示になる。サーバー側で受け付け済みの可能性があるため、自動リトライはしない。

## Xserverでの設定手順（今回未実施）

1. 正式な送信先と差出人を決定する。差出人はサイトのドメインに属するメールアカウントをXserver側で作成・確認する。メールパスワードはコードに不要。
2. 対象ドメインのPHPを8.3以上にし、HTTPSを有効にする。標準の`mail()`、セッション、JSON、filter、PCREが使用可能であることを確認する。PHPのエラー詳細を画面に表示する設定は無効にする。
3. 本PRの公開ファイルを通常のサイトディレクトリへ配置する。`index.html`と`js/contact-form.js`に加え、`api/contact.php`と`api/contact-lib.php`の両方が必要。GitHub Pagesだけへの配置では送信できない。
4. **公開ディレクトリの外**に`portfolio-private/`を作る。標準配置が次の場合、設定は自動で見つかる。

   ```text
   /home/アカウント/ドメイン/
     public_html/
       index.html
       js/contact-form.js
       api/contact.php
       api/contact-lib.php
     portfolio-private/
       contact-config.php
       rate-limit/          # PHPが作成（または事前作成）
   ```

5. `config/contact-config.example.php`を`portfolio-private/contact-config.php`へコピーして編集する。空欄のままでは送信されない。実際の設定ファイルをリポジトリや`public_html`内に置かない。

   | キー | 設定内容 |
   | --- | --- |
   | `to` | 正式な送信先1件。表示名や複数アドレスを付けず、ASCIIメールアドレスのみ |
   | `from` | Xserver上で使用する固定差出人1件。半角英数字から始まる通常のASCIIアドレス |
   | `origin` | フォームを公開する正確なオリジン。例：`https://nmhr12.com`。末尾の`/`、ページのパスを付けない。wwwの有無も一致させる |
   | `rate_secret` | 下記で生成するランダム値。Gitへコミットしない |
   | `rate_dir` | 公開範囲外の保存先。サンプルの`__DIR__ . '/rate-limit'`を推奨 |

   ```sh
   php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
   ```

6. 設定ファイルを600、非公開ディレクトリを700を目安に、PHP実行ユーザーだけが読める・書ける権限にする。`rate-limit`の親は事前に存在する必要がある。777にしない。標準配置と違う場合、PHP実行環境の`PORTFOLIO_CONTACT_CONFIG`に絶対パスを設定できる。設定ファイルも保存先も公開範囲外であることをコードが検査する。
7. サイトをサブディレクトリに置く場合（例：`public_html/portfolio/api/`）、自動探索先は`public_html/portfolio-private/`になり安全検査で拒否される。環境変数が設定できなければ、公開ディレクトリ直下に`api/`を置き、**formのactionだけ**を正しい同一オリジンのAPIパスへ変更する。公開範囲内へ設定ファイルを移して回避しない。
8. Xserverのメール・DNS設定でSPF、DKIM、DMARCと実際の差出人ドメインの整合性を確認する。外部DNSを使う場合はその管理先で確認する。SMTP認証情報は不要だが、Xserver側の配送制限・迷惑メール判定は別途適用される。
9. ブラウザで準備中表示が入力案内へ変わることを確認し、関係者の了解したテスト宛先へ1回送信する。送信成功表示、受信箱・迷惑メール、文字化け、返信時の宛先が入力アドレスになることを確認する。これらの実送受信テストは今回未実施。
10. 設定を無効化する場合は非公開設定ファイルを退避し、ページを再読み込みする。準備中表示へ戻る。

`config/contact-config.example.php`・この資料・テストスクリプトは公開配信に不要。実際の設定値や保存ファイルはGit管理しない。
PHPがソースとして配信されるサーバー構成で運用しない。APIの応答にPHPコードが含まれていたら公開設定を修正する。

## セキュリティ・検証ルール

- サーバーで必須・形式・型・最大長を再検証：名前100、メール254、本文2000。長さはHTML/JSと同じUTF-16単位（絵文字は通常2単位）。
- 種類は空欄または既存の3選択肢のみ。メールはASCIIの単一アドレス。制御文字・ヘッダー改行・配列入力を拒否。
- 本文はHTMLメールにしない。ユーザーの名前・種類を件名やメールヘッダーへ連結しない。
- POSTはJSONのみ、最大16KiB。任意メソッド・不正JSONを拒否。
- 32バイトのランダムCSRFトークン、1時間有効、セッションと照合。成功後は破棄して同じリクエストの再送を拒否。
- セッションはStrict SameSite、HttpOnly、本番HTTPSでSecure、APIディレクトリ限定のCookie。厳格なセッションIDモードを使用。
- POSTのOriginを設定値と完全一致で照合。Fetch Metadataがある場合は同一オリジンだけ許可。CORS許可ヘッダーを付けない。
- ボット用の非表示入力と最低3秒の入力時間。これだけで自動送信を完全に防げるわけではない。
- PHPのセッションを変えても、同じ送信元IPの試行は60秒に1回・15分に5回まで。成功と配送失敗の両方を数える。転送ヘッダーのIPは信用しない。
- ファイルロック付きの共有保存先で、同時リクエストを制限。保存に失敗したら送信しない。アクティブな記録数とファイルサイズにも上限を設ける。
- 保存するのは秘密鍵付きIPハッシュと時刻のみ。生IP、名前、メールアドレス、本文はアプリ独自ログや制限ファイルに残さない。
- 15分を過ぎた時刻は次回の制限処理で削除。送信がなければ最後のハッシュと時刻が残るため、必要に応じて管理者が非公開ファイルを定期削除できる。削除すると制限履歴もリセットされる。
- PHPの内部エラー内容をレスポンスに含めない。Xserver既定のアクセスログ・メール配送ログは別管理であり、今回変更しない。
- IPを変えるボットを完全には止められない。継続的な迷惑送信があれば運用状況に応じて追加対策を検討する。
